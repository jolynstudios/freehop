# From prompt to connected platform

Use an AI coding agent to scaffold a Three.js game, prototype an Electron app, or build your own community space. Freehop provides the same JavaScript API whether you write the code yourself or pair with an agent.

Freehop does not ship an AI model, hosted assistant, transcription pipeline or agent runtime. If your platform needs AI NPCs, a copilot or moderation, choose and connect those services in your own application. Keep provider secrets on your backend and make any sharing of voice, video or messages with an AI service explicit to participants.

## A build brief you can use

```text
Build a small browser co-op prototype using Three.js and Freehop.

Read Freehop's Quickstart and public client API before writing code.
Use freehop@alpha and keep the rendering and connection layers separate.

- My backend authenticates users and issues session tickets.
- Start with microphone and camera off. Enable each only after a click.
- Attach incoming media tracks to my own HTML call panel.
- Share small, validated player events, throttled below 20 per second.
- Show the actual path: direct, gateway, relay, bridged or unreachable.
- Handle missing permissions, blocked playback and connection failures.
- Leave the session and dispose Three.js resources on navigation.
- Keep keyboard, touch controls and a 2D fallback usable.
- Test two independent browsers, peer departure and media shutdown.

Do not invent SDK methods or claim production reliability.
Do not put authority secrets, provider keys or gateway signing keys
in the browser. Do not add an AI service or upload media by default.
```

Start with the [Quickstart](./quickstart.mdx), [client reference](./sdk/client.mdx) and [Three.js guide](./games.mdx). A build brief is a starting specification; review the resulting code and test it on your target devices and networks.

## Build the platform you have in mind

| Idea | Freehop’s role | Your application supplies |
|---|---|---|
| Co-op world with an AI NPC | Human voice/video and small session events | NPC model, provider backend, game rules |
| Shared creation workspace | People talking inside the canvas | Editor, persistence and collaboration model |
| Electron community app | Session client and optional desktop gateway | Accounts, navigation, packaging and updates |
| Human + AI support room | Human participants and media controls | AI integration, consent flow and moderation |

## Keep the integration reviewable

Check that every generated method exists in the [SDK reference](./sdk/client.mdx). Validate incoming messages, test reconnect and leave flows, and inspect what network requests the app makes. Publish the alpha limitations alongside your prototype.

For a concrete foundation, remix [Hopper](/hopper) for squad comms or the [live demo](/demo) to inspect the calling layer. The SDK, protocol and examples are open source; you can inspect the whole path from a player action to a peer connection.
