[Redline Wars](https://redlinewars.online) is a real-time strategy game that runs in the browser and as a desktop app ([source on GitHub](https://github.com/jolynstudios/redlinewars)). It is one planned consumer of Freehop. Freehop is an independent SDK: the game uses its public API, just like any other app.

:::info[Status: integration in progress]

Freehop is being integrated into Redline Wars. Voice and video are not live in the game yet. The integration, including the game's strict frame-time checks with voice switched on, is the next step of Freehop's [verification](./results.mdx#not-yet-verified).

:::

## Why a game is a good first test

A multiplayer game puts all of Freehop's moving parts in one place:

- **A mix of browsers and desktop apps.** Desktop participants can open their own front door with a [gateway](./concepts/gateways.mdx); browser participants benefit from it.
- **Every match already has a host.** The machine that hosts a match is a natural [host node](./concepts/host-nodes.mdx): it belongs to the session, so relaying for the session does not put media on the game owner's servers.
- **Real networks.** A game's participants connect from whatever networks they have, which is exactly the evidence simulated NAT profiles in a home lab cannot provide.
- **A demanding client.** A real-time game must keep its frame rate while voice runs alongside it.

## The planned integration

Each part of the game maps onto one piece of the SDK:

| In the game | Freehop piece | What it does |
|---|---|---|
| The lobby and room service | [Authority](./sdk/authority.mdx) | Creates a 32-byte secret per room and delivers each member's ticket with the lobby join response it already sends, never in a room listing. A kick rotates the secret for the remaining participants. |
| A small service next to the existing relay | [Gate](./sdk/gate-service.mdx) | Runs as a separate service with a token secret. Tickets carry room-bound gate tokens, so the gate serves only the game's own rooms. A community gate list may be added; clients use all gates and survive any of them going down. |
| The node that hosts a match | [`hostSession()`](./sdk/host.mdx) | A participant's desktop app or a community server that hosts the match joins its room as a gateway member. The game owner's own nodes must not do this, so the owner never carries media. |
| The desktop client | [`installFreehopGateway()`](./sdk/desktop.mdx) | Runs the participant's gateway in the Electron main process, so participants behind hard NATs or UDP-blocking networks can reach desktop participants without any third party. |
| The in-game interface | [`connect()`](./sdk/client.mdx) | Voice and video are opt-in per participant. The interface shows the path to each participant, and "voice unavailable on this network" when a pair is `unreachable`. |

One deployment detail: the game origin's `Permissions-Policy` header must allow `camera` and `microphone` once voice ships.

## Where the torrent trackers fit

The [live call](/demo) on this site uses public WebTorrent trackers as its only gates: browsers find each other through trackers that BitTorrent apps in the browser already use, with no server of ours. [Torrent trackers as gates](./concepts/trackers.mdx) explains how that works.

In the game, the main mailbox is the game's own gate. It runs on the game's own domain and admits only tickets for the game's own rooms. Public trackers can be listed in the same tickets as backup gates:

- **If the game's gate is down or blocked** on someone's network, participants still find each other through a tracker. A call that is already running does not need any gate.
- **The trackers cannot read match signalling.** They see an opaque swarm fingerprint, IP addresses, random peer ids, sizes and timing. Match names and user ids are not sent, but metadata can still correlate participants. Voice never passes through the tracker.
- **The trade-off.** Public trackers are run by volunteers, outside the game's control. Whether the game lists them is a decision for the integration.

## What the game does not get

The game gets no special treatment from Freehop. It uses the same tickets, the same gates and the same path ladder as any other application, and nothing in the SDK is specific to games.
